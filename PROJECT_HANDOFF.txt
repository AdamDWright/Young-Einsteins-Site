Young Einsteins Website Project Handoff
======================================

Purpose
-------
This repository contains the Young Einsteins tutoring website: a Vite +
Tailwind build with an EN/VI language toggle, Web3Forms contact form, GA4
analytics, a cookie notice, and a small ESLint/Prettier setup. This file
summarises the current structure, content, behaviour, and deployment plan.


Current Stack
-------------
- Vite (dev server, build, HTML partials via posthtml-include)
- Tailwind CSS v4 (all styling)
- Vanilla JavaScript (nav, scroll-reveal animation, EN/VI toggle, contact
  form with rate limiting, cookie banner)
- Web3Forms (contact form delivery, no backend)
- Google Analytics 4 (visitor analytics)
- ESLint + Prettier (flat config - see note below)
- No Flask, no Python backend, no SQL database, no login system, no admin
  dashboard, no payment processing
- Intended hosting: GitHub Pages, built and deployed via GitHub Actions

Design Direction
----------------
- Tailwind utility classes plus a small set of reusable component classes
  (.btn-primary, .btn-secondary, .card, .tag, .nav-link) defined in
  src/css/main.css
- Brand colours (blue, yellow, red) carried over from the original site,
  defined as Tailwind theme colours (brand-blue, brand-yellow, brand-red)
- Poppins font from Google Fonts
- Deliberately soft edges: hard 100%-opacity border lines have been reduced
  or removed throughout (hero section dividers, card borders, stat-box
  borders) in favour of shadow-only definition or low-opacity borders -
  keep this in mind when adding new sections; avoid reaching for a solid
  `border-slate-200` unless there's a functional reason (e.g. form inputs)
- Scroll-reveal animation: a fade-up (opacity + slight translateY), see the
  next section for the safety mechanism, hover lift/shadow on cards and
  buttons, smooth mobile nav slide-down
- Mobile header: brand lockup collapses to logo-only below the sm
  breakpoint; nav becomes a slide-down panel so it doesn't crowd the
  hamburger and language toggle
- Footer redesigned as a multi-column layout (brand+ABN, quick links,
  contact, social) on a gradient/dot-pattern background instead of a flat
  colour bar
- Homepage testimonials: a continuously auto-scrolling marquee
  (src/js/reviews.js + .marquee/.marquee-track in main.css) built from real
  anonymised client feedback, duplicated once in the DOM so the CSS
  translateX loop is seamless. All cards share one height via flexbox
  stretch, so an unusually long quote makes every card taller - keep quote
  lengths roughly even when adding new ones.
- Contact form's Comments/Request field has a 1000-character maxlength and
  a live "N characters remaining" counter (src/js/form.js), styled light
  grey under the box and re-rendered on language toggle via a
  `languagechange` event dispatched from applyLanguage() in i18n.js.


Scroll-Reveal Safety Mechanism (read before touching .reveal)
----------------------------------------------------------------
Elements with the `.reveal` class are FULLY VISIBLE by default in CSS. Only
`src/js/main.js` adds the `pre-reveal` class (which is what actually hides
content, via `opacity: 0` + a slight `translateY`, then fades/slides up
once `is-visible` is added), and only once it has confirmed
`IntersectionObserver` is available. This is deliberate: an earlier version
hid `.reveal` elements by default in CSS and revealed them via JS, and a
timing/runtime issue left real content (subject cards, About page sections)
permanently invisible in production - a rebuild without a corresponding CSS
change would have been indistinguishable from missing content. Do not
reintroduce a default-hidden state in CSS for any future animation; always
have JS opt an element INTO a hidden state, never opt it out of one.


EN / VI Language Toggle
------------------------
- All translatable strings live in src/js/translations.js as
  { key: { en, vi } }
- HTML elements needing translation carry data-i18n="key" (text content),
  data-i18n-html="key" (same, but sets innerHTML - only for keys whose
  translation intentionally contains simple markup like <strong>, never
  user input), or data-i18n-attr="attr:key" (for attributes like
  placeholders)
- A toggle control ("EN / VI" with a divider) lives inside the shared nav
  partial, visible on both desktop and the mobile nav panel
- Selected language persists in localStorage ("ye-lang") and is re-applied
  on every page load, since this is a multi-page site, not a single-page app
- The Vietnamese strings are a best-effort AI translation and should be
  proofread by a native/fluent speaker before launch
- privacy.html and terms.html are fully translated and work with the toggle
  like every other page - the translate() function has no exceptions for
  them


Contact Form (Web3Forms)
-------------------------
- Fields: student's full name, parent/guardian name, student year level,
  mobile number, email, subject needed, lesson type, comments/request
- A hidden "botcheck" checkbox field is included for Web3Forms' spam
  filtering
- Rate limiting: on successful submit, the timestamp is written to
  localStorage; a resubmission within 15 minutes shows a "please wait"
  message instead of sending again. The submit button is also disabled the
  instant it's clicked (before validation even runs) to stop double-submits
- On submit: client-side validation runs first (src/js/form.js), then a
  POST to https://api.web3forms.com/submit via fetch with the form's access
  key
- Status messages ("Sending...", success, fallback error, rate-limited) are
  language-aware
- Fallback behaviour: if the access key is missing or the request fails,
  the fallback message directs people to call 0404 865 516 or email
  young.einsteins@outlook.com - the form must never fail silently
- IMPORTANT: the Web3Forms destination inbox (where enquiries actually
  land) is set when the access key is created on web3forms.com, NOT in this
  codebase. To have enquiries sent to the real business inbox, create/
  verify the Web3Forms access key using young.einsteins@outlook.com (the
  address already shown across the site), then paste the resulting key
  into contact.html's data-web3forms-access-key attribute.

Deployment Plan
----------------

Repository ownership:
1. Adam creates and finishes the site locally.
2. Adam pushes it to a GitHub repository.
3. Adam transfers the repository to the Young Einsteins GitHub account.
4. Young Einsteins becomes the repository owner.
5. Adam remains a collaborator/contributor.

Build/deploy workflow:
- .github/workflows/deploy.yml runs on every push to main: npm ci, npm run
  build, then uploads ./dist via actions/deploy-pages

  build first, hence the Actions workflow

Future update workflow:
1. Edit files locally.
2. npm run dev to preview.
3. Commit changes.
4. Push to GitHub - Actions builds and deploys automatically.


Custom Domain Plan
-------------------
- Domain: youngeinsteins.com.au, bought and renewed by the client through
  Quantum Core (quantumcore.com.au), an Australian registrar/host. DNS is
  managed there via Client Area -> Domains -> Manage DNS, unless the
  domain's nameservers have been pointed elsewhere.
- GitHub Pages hosting is free. public/CNAME already contains
  youngeinsteins.com.au, so it's built into every deploy.
- Add custom domain in: Repository -> Settings -> Pages -> Custom domain
- DNS records needed at the registrar:
  - Apex (youngeinsteins.com.au): four A records to GitHub Pages' shared
    IPs - 185.199.108.153, 185.199.109.153, 185.199.110.153,
    185.199.111.153 (verify current values in GitHub's own Pages docs -
    they're long-stable but GitHub is the source of truth).
  - www subdomain: one CNAME record to <owning-github-username>.github.io
    (GitHub then auto-redirects www -> the apex domain set above).
- Enable "Enforce HTTPS" in GitHub Pages settings once DNS has resolved and
  GitHub has verified the domain (the checkbox is greyed out until then).
- If the repository is later transferred to a different GitHub account
  (see "Repository ownership" below), GitHub Pages does NOT auto-redirect
  the old owner's *.github.io - the www CNAME record above must be updated
  to point at the new owning account's *.github.io right after transfer.
- If NOT using a custom domain (i.e. served at username.github.io/repo-name
  instead of the domain root), update `base` in vite.config.js to
  "/repo-name/" before building.

Deliberate Deviations From The Original Brief Document
-----------------------------------------------------
- tailwind.config.js was NOT added. Tailwind v4 (installed here) uses a
  CSS-first `@theme` block via the `@tailwindcss/vite` plugin and does not
  use a JS config file - adding an empty/legacy-style one would be actively
  misleading.
- eslint.config.js (flat config) was used instead of .eslintrc.js. The
  ESLint version that installs today no longer treats .eslintrc.js as its
  primary config format; flat config is the current equivalent.
- vite-plugin-posthtml (named in some earlier notes) is unmaintained since
  2021 with no version compatible with current Vite. vite.config.js instead
  calls `posthtml` + `posthtml-include` directly via a small custom plugin.
- public/favicon.ico was not created as a binary file; instead
  src/partials/head-assets.html references the existing logo.png as the
  favicon via a standard <link rel="icon" type="image/png"> tag.
- The logo asset stays in public/assets/ (Vite's static-passthrough
  convention) rather than src/assets/images/ as originally sketched, to
  avoid the asset-path resolution issues that come with moving it into the
  processed src/ tree.
